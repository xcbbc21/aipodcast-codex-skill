# Narration design: density, flow, and endings

Use this reference whenever rewriting a script for listening.

## Episode shape follows the material

An episode needs enough context to stand on its own, a clear path through the author’s reasoning, and an ending that leaves the listener oriented. It does not need a fixed number of paragraphs, sentences, questions, or minutes.

Keep distinct mechanisms distinct. If the source has three separate causes, listeners may need “第一、第二、第三” or equally clear transitions. Do not flatten a meaningful list into one crowded paragraph just to avoid numbering.

For a short transition or summary, speak the actual point and finish. For a dense lecture, retain the evidence and explain the steps. If the user imposes a time limit that conflicts with complete coverage, identify the conflict and offer a long complete episode or a user-approved split; do not silently cut the argument.

## Openings and transitions

Start with the problem, scene, or conclusion that the source actually develops. Add chapter framing only when it helps the listener locate the current argument. Do not recite headings such as “开场钩子” or “本讲核心问题.”

Use transitions to name the relationship between ideas: cause, contrast, example, objection, condition, or consequence. Avoid repeated stock phrases across a series.

## Ending recipe

Write the last passage in this order when applicable:

1. Return to the central question and state the episode’s answer or boundary.
2. Offer one main reflection question if reflection adds value.
3. Add a final spoken landing: a concise conclusion, a verified connection to the next episode, or a chapter close.

The last audible sentence must be a landing, not a question list.

### Question choices

| Kind | Use when | Rule |
| --- | --- | --- |
| Recall question | The listener needs to distinguish a key mechanism or condition | Its answer is already in the episode |
| Transfer question | The listener can apply the explained mechanism to a simple hypothetical | Mark the hypothetical clearly; do not add unverified facts |
| Next-episode question | The next episode genuinely examines the issue | Verify the next episode before using it; do not imply its answer is already proven |

If the user explicitly requests three questions, make them a short progression rather than three parallel prompts, then add the landing sentence. Do not force “mechanism, condition, test” wording into every episode.

## Series review

Before delivering a batch, read the final two paragraphs of every episode in sequence. Revise repeated question stems, repeated farewell phrases, generic suspense, and endings that need the listener to infer whether the episode is over.
